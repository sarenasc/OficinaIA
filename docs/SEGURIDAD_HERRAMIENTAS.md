# Seguridad de herramientas — Etapa 3

- API local autenticada, sin exposición nueva fuera de localhost. PostgreSQL/Redis conservan loopback; el sandbox no publica puertos.
- Cada llamada valida asignación, capacidades y JSON Schema. El modo trusted no omite permisos; las escrituras SQL/API requieren aprobación independiente.
- Los secretos se guardan en Windows Credential Manager y se resuelven al ejecutar, nunca se incluyen en las instrucciones del agente. El perfil backend Linux no tiene acceso al vault de Windows; no hay fallback en texto plano.
- Web requiere recursos URL explícitos. Cada solicitud y redirección verifica esquema/origen/ruta, resuelve DNS con límite y deniega IPs privadas/reservadas/metadata. La conexión usa la IP ya validada y TLS con el hostname original, evitando una segunda resolución del nombre. No se usan proxies ambientales. Se rechazan escapes de ruta, userinfo y downgrade HTTPS→HTTP.
- API: base configurada, endpoint relativo, redirecciones entre orígenes con credenciales denegadas. allow_private exige autorización por tarea y una procedencia configurada; las herramientas web no disponen de esa excepción. Credenciales solo por HTTPS.
- La excepción privada no habilita destinos link-local de metadatos ni direcciones multicast/indeterminadas/reservadas especiales.
- HTTP: 30 solicitudes/minuto por agente/destino por defecto (configurable 1–60 para APIs/búsqueda), 10 MB, timeout total y límite de redirecciones. Respuestas comprimidas no se aceptan. Estas herramientas no eluden captchas ni ejecutan JavaScript descargado.
- Dataset: extensión y MIME permitidos; JSON parseado, CSV UTF-8 y XLSX validado con límite de expansión ZIP. No se ejecutan descargas. No hay OCR.
- Archivos: resource_path deniega escapes, symlinks y junctions; publication verifica SHA-256, usa creación exclusiva o reemplazo preparado, comprueba cambios concurrentes y vincula aprobaciones de sobrescritura al contenido.
- Python: contenedor usuario 10001, sin red, rootfs read-only, cap_drop ALL, no-new-privileges, 1 CPU, 512 MB, 64 PIDs, tmpfs 64 MB, máximo dos ejecuciones simultáneas por backend. Sin socket Docker ni secretos; staging hasta 50 MB/1000 archivos por recurso, captura limitada y timeout con eliminación del contenedor. Docker ausente nunca causa ejecución directa en el host.
- SQL: SELECT validada con funciones permitidas, parámetros vinculados, límite de filas y timeout. SQLite abre mode=ro para lectura. DML solo con conexión habilitada, tablas autorizadas y aprobación; transacción/rollback y límite de filas afectadas. Los motores reales necesitan cuentas con permisos mínimos: la aplicación no reemplaza los controles del servidor.
- PDF: máximo 20 MB/200 páginas, texto acotado, recursos de imágenes autorizados, XML de texto escapado, sin fuentes remotas ni OCR. Merge no conserva anotaciones/acciones de página. PDF interactivos, firmados o formularios requieren un flujo especializado; no se garantiza conservación de esas propiedades.
- Execution/AuditEvent/Artifact conservan estado, error, duración, rutas verificadas y cambios aprobados; la redacción existente se aplica. El contenido leído se trata como datos no confiables, nunca como instrucciones del sistema.

Límites conocidos: dependencias PDF operan en el backend con entradas locales autorizadas y límites; no se añadió un sandbox PDF separado. El lanzamiento de Python necesita backend nativo y Docker Desktop. Los permisos de archivos no constituyen bloqueo de sistema operativo contra otro usuario local que modifique simultáneamente rutas. La cancelación explícita de tareas no interrumpe instantáneamente una llamada HTTP/SQL ya enviada: se limita por su timeout; Python se cancela al exceder su límite. No se incorporan paquetes automáticamente.

Una API externa puede confirmar una escritura y perderse la respuesta de red. No hay garantía universal de ejecución exactamente una vez: no repitas una escritura cuyo resultado es incierto sin revisar el servicio externo. Los conectores sociales con OAuth, aprobaciones de publicación por contenido e idempotencia específica siguen pendientes. api.request es una integración HTTP configurable, no un publicador automático de redes sociales.
